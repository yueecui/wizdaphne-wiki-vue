# 技能参数标注（`EffectKind.params` 的 `@xx`）

> 最后更新：2026-11-07
> 适用对象：维护 `Data:EffectKind.json` 参数名、或改技能详情数值展示的人。

技能详情里每个子效果都按 `param_1..7` 显示数值。这些数值的含义写在
`Data:EffectKind.json`（线上手工表）的 `params` 数组里，第 N 个字符串对应 `param_N`。

标注有两种后缀，**顺序不能反**：

| 写法 | 含义 | 解析位置 |
|---|---|---|
| `"伤害%"` | 这个数字是百分数，`%` 显示在数值后面 | `PERCENT = /%+$/` |
| `"对应能力值@bp"` | 这个数字是某个枚举的 id，展示时翻译成名字 | `REF_TAG = /@([a-z]{2})\s*$/i` |

`REF_TAG` 要求 `@xx` 在**字符串末尾**，所以两者不能同时使用（`"xxx@bt%"` 不会识别 tag）。
查不到对应名字时原样显示数字。

代码位置：`src/views/DataV2/SkillDetail.vue` 的 `paramTag()` / `paramName()` / `paramValue()` / `refText()`。

---

## 1. 标注格式

`params` 是字符串数组，元素可以是：

- 普通文字：`"威力"` → 直接显示文字 + 数值
- 带 `%`：`"発動率%"` → 数值后加 `%`
- 带 `@xx`：`"对应能力值@bp"` → 数值查枚举后显示名字（查不到显示数字）
- `@xx` 前面可以带任意说明文字，`refText()` 只取 tag 之后的值查表；说明文字在括号里展示
  （例如 `"武器类型@eq"` 会显示成「双手剑」而标签列仍是 `武器类型`）

## 5. 已知问题

1. **5720 用错 tag**：`param_1` 是耐性 / 状态异常的 id
   （28 毒・麻痹・石化、36 即死耐性、42 会心耐性），不是 `buff_target`。
   应换成独立 tag（如 `@rst`）并接耐性表，否则页面全是数字。
2. **两套编号撞车**：`4`（bp 防御力 / bt 攻击力）、`5`（bp 法术防御力 / bt 防御力）、
   `12`（bp 行动速度 / bt 会心）、`14`（bp 命中 / bt 行动速度）。标注时极易写反。
3. **2810 的 `@ef` 值不是效果种类**：`194016702012810` 是技能行 id（`identification*100 + level`），
   应改标 `@sk`。
4. **6520 的 p5 `@eq` 值可疑**：`17003 / 17005` 不像装备类型（类型 id 都是 3 位），
   可能是装备行 id 或另一套编号。
5. **`equipment_type` 字典不全**：`5800` 用到 `300 / 301 / 401 / 501 / 601 / 701`，
   这些值目前解析成裸数字。

## 6. 详情页多动作页签的命名

一个技能有多个顶层效果组时，技能详情会把每个效果组做成一页（页签），
内容是该效果组自己的伤害 / 子效果。页签名按下面顺序取：

1. `SkillEffectGroup.display_name.zhs`（没有则 `zht`）
2. 上面为空时用 `display_name.ja`
3. 仍然为空 → 前端兜底显示 **`技能 N`**（N = 效果组在该技能里的顺序，从 1 开始）

第 3 种是**我们自己的占位命名，不是游戏里的名字**。常见于：

- `display_name` 是占位符 `"-"`（例：7600301「海鸥的装备熟练术」的两个被动效果组，
  显示为「技能 1 / 技能 2」）
- `display_name` 是一整句描述（清洗时按「超过 16 字或带句末标点」过滤掉，
  例「Arch Shadow Lord摆出十亿斩击的架势。」），见 `skill.py` 的 `action_name()`

只有一个效果组时不出页签，详情与改动前完全一致。
